# 京东 v23 搜索播放器预加载实验

依据 2026-10-27 09:03、09:08 两次 Surge HAR 和用户截图：09:03 两条搜索播放器上下文的 MP4 均为奶粉广告素材且返回 200；09:08 截图出现同一活动广告，抓包中未见视频下载。该时序支持预下载后展示的假设，但未直接观测本地文件读取，也不能证明所有开屏都经该路径。

模块新增参数 `search_preload`，默认 `false`。只有手动设为 `true`，才将京东视频 UA、FinalSearchListViewController 播放器 Referer 同时满足且属于 vod.300hu.com、storage.360buyimg.com、discover.300hu.com 三个既有主机的 MP4、M3U8、TS 请求返回 204。按用户要求覆盖这些主机上的不同路径与轮换素材，不局限两条视频；未知新域名或其他媒体格式未覆盖，不能保证完全屏蔽。用户已明确接受该实验可能拦截普通搜索视频；其它播放器、商品详情、直播维持 v22 的处理范围。将参数改回 `false` 可关闭实验。

参数放在原模块对应的三个请求脚本规则上，避免叠加第二模块出现同 URL 只运行第一条脚本的冲突。依据 Surge 官方文档：模块参数可用三重花括号替换并通过 argument 传入脚本；同一请求至多运行一条匹配的请求脚本。https://manual.nssurge.com/profile/module.html https://manual.nssurge.com/scripting/overview.html

安装 v23 后在 Surge 模块参数中设置 `search_preload=true`，启用脚本和 MITM。它不能删除 App 里已经存在的广告；用户自行清理一次京东缓存前应了解可能触发重新登录或移除临时数据。随后强退冷启动，检查开屏、搜索视频、商品详情和播放；若搜索视频异常，将参数改回 `false`。无需卸载京东或清除订单数据。

实验预期是减少后续预下载，不保证立即消失或覆盖其他广告链。HAR 回放只证明规则对已观察请求的处理；缓存机制和真机展示仍需验证。避免将 HAR、账号及素材标识提交仓库。

自动化验证：新增回归测试先在旧实现上失败，修改后 37 项京东测试通过；脚本行覆盖率 96.59%、分支覆盖率 89.29%。09:03 HAR 的两条视频在 false 时透传、true 时返回 204，且按模块规则顺序均能分派。原生解析器对替换参数后的 false/true 配置均通过；JS 语法与模块 lint 通过。全仓 JS 测试 289 通过、26 跳过、2 失败，失败为既有 CMCCHebaoCapture 元数据/README 索引问题。尚未完成设备 UI 验收。
